## Intent

**Problem:** Story 9.1 attaches tickets and booking confirmations to stays and activities, but they exist only inside the app. The printed day plan omits them entirely and silently, and there is no way to take the day's documents offline — which is the one moment they are needed, standing at a gate with no signal.

**Approach:** Two halves, deliberately different mechanisms. The printed day plan (HTML + `window.print()`) appends each **image** document as its own full page and names every **PDF** document in an appendix that says plainly it does not contain them. A new server route merges the day's documents — PDFs page-for-page, images embedded — into one packet PDF with a label page before each, reachable from the day overflow menu. No headless browser in the deployment; one new pure-JS dependency (`pdf-lib`).

## Boundaries & Constraints

**Always:**
- **One source of order.** The day's document list and its order come from `getTripDayPrintPayloadForUser`'s existing `timeline` array (`tripRepo.ts:1223-1282`: `previousStay` → plan items sorted by `compareDayPlanItemsByStartTime` → `currentStay`) flattened by **one shared pure helper** imported by both the print component and the packet route. No second sort, no second traversal, no second definition of "the day's documents".
- **PDF-vs-image is decided by the `documentUrl` extension**, never by `fileName`. The URL's extension is server-generated by 9.1's upload routes from their own `ALLOWED_TYPES`; `fileName` is user-supplied and may lie. Add the predicate to `documentUploads.ts` so both halves share it.
- Document bytes are read **off disk** via `resolveStoredMediaPath` (`uploadPaths.ts:158`) and then containment-checked against `getTripUploadDir(tripId)` (lexical prefix with a trailing separator, then `fs.realpath` against the realpath'd root), mirroring `src/app/uploads/[...path]/route.ts:287`. Never by fetching the app's own URLs over HTTP — after 8.3 the serve route needs a session cookie the server does not have.
- The packet route's guard chain is `requireSession` → `dayRouteParamsSchema.safeParse(await context.params)` → `hasTripReadAccess` → payload → merge, with `export const runtime = "nodejs"`. The middleware gate (`middleware.ts:30,38-52`) is the first layer, the in-route guard the second; both are required, as every sibling route does both. Access failure answers **404 `not_found`**, never 403 (house convention).
- Every per-document step sits in its own `try`/`catch` that produces a label page. A `throw` from one document must never reach the outer handler or shorten the packet.
- Every string drawn into the PDF is sanitised to a guaranteed-encodable WinAnsi subset before `drawText`. `StandardFonts.Helvetica` **throws at draw time** on anything outside WinAnsi, and label pages carry user-supplied file names.
- New user-facing strings exist in `en.ts` **and** `de.ts` under 9.1's `trips.documents.*` namespace (`en.ts:652-676`, `de.ts:605-630`); `i18nDictionaries.test.ts` stays green.
- The day-screen download goes through `fetch` + blob, never `<a download>`: the route answers failures as `{data,error}` JSON and AC6's refusal is exactly what an anchor would save to disk as a file.
- Additive only on the print payload: a day with no documents must produce byte-identical printed output to today's.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| Print, no documents | Day whose stays and items carry no document rows | Printed sheet identical to today's: no image pages, no appendix section, no new DOM | No error expected |
| Print, image documents only | Two `.jpg` documents on one activity | One full page per document after the itinerary, each `page-break-before`, each captioned with the entry label and the file name; no appendix; **no trailing blank page** | No error expected |
| Print, PDF documents only | One `.pdf` on a stay, one on an item | No image pages; appendix listing `<entry label> — <file name>` per PDF plus the sentence stating they are not included and where to get them | No error expected |
| Packet, happy path | Day with a 3-page PDF on the previous-night stay and a portrait JPEG on an activity | `200 application/pdf`, `content-disposition: attachment; filename="<trip-slug>-day-<n>-documents.pdf"`; 6 pages: label, 3 copied pages, label, 1 image page; order = timeline order; the portrait JPEG is upright | No error expected |
| Packet, unauthenticated | No `session` cookie | `401 unauthorized` | `requireSession` envelope |
| Packet, non-member | Valid session, trip belongs to someone else | `404 not_found` | `hasTripReadAccess` false → 404, not 403 |
| Packet, viewer member | `TripMember` role `VIEWER` | `200 application/pdf` | Read access is the gate, not ownership |
| Packet, empty day | Read access, day exists, zero document rows | `404` with code **`no_documents`** and its own message | Distinct from `not_found`; client maps it to its own string |
| Packet, day of another trip | `dayId` valid but belongs to a different trip | `404 not_found` | Payload builder scopes the day by `{ id: dayId, tripId }` |
| Packet, encrypted PDF | Source PDF whose trailer carries `/Encrypt` | Label page naming the file and saying it could not be included; every other document still merged; overall `200` | `PDFDocument.load` throws → caught per document |
| Packet, corrupt / truncated PDF | Bytes that are not a parseable PDF | Same degradation label page | Caught per document |
| Packet, missing file on disk | Row exists, file unlinked | Same degradation label page | `fs.readFile` `ENOENT` caught per document |
| Packet, `.webp` document | Image document stored as WebP | Same degradation label page — `pdf-lib` has only `embedJpg`/`embedPng` | Refused before embedding, by extension |
| Packet, non-WinAnsi file name | `fileName` = `Εισιτήριο — Ρώμη.pdf` | Label page drawn with unencodable characters replaced by `?`; packet completes | Sanitised before `drawText`, never thrown |
| Packet, URL escaping the trip dir | Hand-corrupted `documentUrl` containing `..` | Degradation label page; nothing outside `getTripUploadDir(tripId)` is read | Containment failure treated as an unreadable document |
| Download, failure envelope | Route answers `no_documents` | Day screen shows the empty-day message; **nothing is written to disk** | `fetch` inspects the envelope before `blob()` |

**Acceptance Criteria:**

- Given a day with image documents, when it is printed, then each one occupies its own page after the itinerary, fits inside the A4 `16mm 14mm` box without cropping or distortion, is oriented as the browser displays it, and the last one is followed by no blank page.
- Given a day with PDF documents, when it is printed, then an appendix names every one of them by entry and file name and states in the printed output that these files are not included and that the packet is where to get them.
- Given a day with no documents at all, when it is printed, then the output is byte-for-byte what it is today — no image pages, no appendix, no new element.
- Given a day whose documents span the previous night's stay, two activities and tonight's stay, when the packet is requested, then the merged PDF contains every one of them in exactly the day timeline's order, each preceded by a label page naming the entry and the file name, with source PDFs kept page-for-page at their own page size.
- Given one document that cannot be merged among nine that can, when the packet is requested, then the response is `200` and contains ten label-page groups, the failing one saying so and naming the file.
- Given a trip member with the `viewer` role, when they request the packet, then it is produced; and given a user with no access, then the response is `404 not_found` with no bytes.
- Given the day overflow menu at 390px **and** at 747px, when it is open, then the packet item and every sibling item measures at least 44px, and activating the packet item saves a `.pdf` — never a JSON envelope — while a refusal shows a message distinct from "trip not found".
- Given `npm test`, `npx tsc --noEmit`, `npm run lint`, `npm run check:migrations` and `npm run audit:check`, when they run after the change, then the recorded baselines hold with no assertion weakened and no new advisory.

**Why the two halves orient images differently.** Browsers default to `image-orientation: from-image`, so the HTML print half gets EXIF rotation free. `pdf-lib` reads only the JPEG SOF dimensions, so a phone photo storing landscape pixels plus `Orientation: 6` embeds sideways. There is no image library in the tree — `sharp` sits in `overrides` only — so the packet half parses the APP1 segment itself: find `FFE1`, check the `Exif\0\0` marker, read the TIFF byte order (`II`/`MM`), walk IFD0 to tag `0x0112`. Orientations `1/3/6/8` are handled exactly; the four mirrored values `2/4/5/7` fall back to their nearest rotation (`2→1`, `4→3`, `5→8`, `7→6`) with the mirror left uncorrected and a comment saying so — they do not occur on phone cameras, and an honest approximation beats an unread branch.

Rotating in `pdf-lib` needs the translation, because `rotate` pivots on the bottom-left corner:

```ts
// 90° clockwise: the drawn box is h×w, and the origin moves to the top-left
page.drawImage(img, { x: drawX + drawH, y: drawY, width: drawW, height: drawH, rotate: degrees(-90) });
```

**Two shapes to leave alone.** Copied PDF pages keep their own page size, so the packet is legitimately mixed-size — rescaling someone's boarding pass to a uniform sheet is worse. And the label page sits *before* each document rather than being drawn onto its first page, which would risk landing on a barcode.

**Why a label page beats nothing for a failure.** A traveller who finds nine tickets and one page reading "this file could not be included — open it from the app" can act. A packet that is nine tickets long with no explanation, or that 500s because of the tenth, cannot be acted on at a gate. This is why AC5 is a per-document `catch` rather than a validation step.

**React Compiler is on and bails out loudly.** Story 6.26 recorded two edits that silently stopped a whole component compiling, both surfacing only in `eslint`. If lint output changes shape in `TripDayView.tsx` or `TripDayPrintDocument.tsx`, diff against `git show HEAD:<file>`.

**Two test-quality rules this project's reviews enforce.** Never assert a height or a computed layout value in jsdom — it resolves `height` to `""`, so the assertion passes whether the code is right, wrong or absent (6.26's review found exactly this masquerading as proof). And pin each degradation with a fixture verified to fail without the fix: a genuinely `/Encrypt`-carrying PDF and a genuinely truncated one, not a `vi.fn()` that throws.
