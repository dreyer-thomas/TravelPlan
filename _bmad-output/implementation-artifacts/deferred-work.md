Strictly outside AC6, which named contained buttons only — but `EXPERIENCE.md:104` makes visible focus an unconditional baseline, so the gap survives 7.11. Fix is an `MuiIconButton` `&.Mui-focusVisible` treatment alongside the `MuiButton` one. Note that plain links correctly fall back to the UA ring and need nothing.
- **`bmad-loop confirm` sets the frontmatter status but not the body's `Status:` line, so every confirmed story drifts** [`_bmad-output/implementation-artifacts/*.md`] — the spec template carries the status twice: once in YAML frontmatter and once as a `Status:` line in the body (plus a third time in `## Auto Run Result`). `confirm` writes only the frontmatter and appends its Operator Confirmation block, then leaves the body untouched — which is why each story's final `operator_actions` entry has to ask the human to "set status: done in BOTH the frontmatter and the body's 'Status:' line" by hand. 7-9 drifted exactly there; 7-11 drifted the same way minutes later despite its own action 10 explicitly warning against repeating it. So this is a structural property of the tool, not operator error, and it will recur on every future park. Fix is either teaching the confirm path to rewrite the body line, or removing the duplicate status from the template so the frontmatter is the only source.
