(Note: a sibling finding, `react-hooks/immutability` at `TripDayView.tsx:682`, was originally grouped with these but turned out to be a real stale-closure bug rather than a false positive — it was fixed directly as part of this change instead of deferred.)
- **`brace-expansion`/`minimatch@3.1.5` npm audit finding cannot be fixed without breaking the lint toolchain** [travelplan/package.json] — GHSA-mh99-v99m-4gvg (high, DoS), required directly by ESLint 9 core (`@eslint/config-array`, `@eslint/eslintrc`) and by `eslint-config-next`'s bundled `eslint-plugin-react`/`-import`/`-jsx-a11y`; no patched 1.x release of `brace-expansion` exists for this CVE. Tried three fixes: ESLint 9→10 (breaks — bundled `eslint-plugin-react` uses an API ESLint 10 removed), forcing `brace-expansion` to v5 (crashes ESLint's glob matcher), forcing `minimatch` to v9 (doesn't crash but silently changes ignore-pattern matching, surfacing false-positive lint errors). devDependency-only, never ships, requires attacker-controlled glob input to trigger — unexploitable in this repo. `npm audit --omit=dev` is 0; this is the sole remaining finding in the full audit. Blocked on Next.js shipping a newer `eslint-config-next` with an ESLint-10-compatible `eslint-plugin-react`.
- **No lockfile provenance/signature verification in the security-hardening pass** [travelplan/package-lock.json] — `npm audit signatures` and general supply-chain provenance checking (compromised transitive deps, dependency confusion) were out of scope for this change (which targeted known-CVE remediation), but surfaced by adversarial review as a real gap for a "security hardening" effort. - **No scheduled re-audit for already-merged dependencies** [`.github/workflows/security-audit.yml`] — the new gate only runs on `push`/`pull_request`, so a dependency that's already merged and untouched won't get re-checked when a new CVE is disclosed against it tomorrow. - **No override/allowlist mechanism if a future production-dependency CVE has no upstream fix** [`travelplan/package.json`'s `audit:check` script] — today's unfixable finding (brace-expansion) happens to be dev-only, so `--omit=dev` sidesteps it cleanly. Not needed now (production audit is 0), but worth designing before it's urgently needed.

## Deferred from: code review of 7-2-trip-overview-redesign (2026-07-31)

- **New hardcoded hex/rgba literals contradict Story 7.1's token foundation** [`TripTimeline.tsx:153`] — `HERO_SCRIM`, `DAY_ROW_GAP_BG = "#FBF6EE"` (a fourth near-duplicate of `warnBg`/`cardAlt`), plus `"#FFFFFF"`, `rgba(255,255,255,.18/.28/.55/.92)`, `"11.5px"` and `p: "16px 24px"` literals throughout the hero/stat-strip/day-row/sidebar. Several are spec-mandated literal values (the 4-stop scrim, the mockup's `#FBF6EE`, white-on-photo alphas), so this is not a straight defect — but retheming (dark mode, brand change) now requires editing component bodies again, which is what 7.1 set out to eliminate. The story already flags the `#FBF6EE` vs `colors.warn-bg` `#F6ECE0` conflict between the mockup and DESIGN.md's token table; that reconciliation pass is the natural home for this.
- **Four one-off SVG icon components inlined in `TripTimeline.tsx`** [`TripTimeline.tsx:92-151`] — `HouseIcon`, `WarningTriangleIcon`, `ChevronRightIcon`, `ShareGlyphIcon` are private to this file, but Story 7.3 (Day Detail) needs the same house and warning glyphs and will duplicate them. Each also types its prop as `sx?: object` rather than `SxProps<Theme>`, so style-key typos go unchecked. Extract to a shared icon module when 7.3 needs them, rather than pre-emptively now.
- **`data-layout` re-derives the breakpoint in JS, duplicating the CSS grid's source of truth** [`TripTimeline.tsx:623`] — layout is driven by `sx` responsive objects, but `isNarrowLayout` (`useMediaQuery(theme.breakpoints.down("sm"))`) also stamps a `data-layout="stacked"/"inline"` attribute purely so tests can assert something jsdom cannot compute. Change one breakpoint and the attribute reports "inline" while the CSS renders stacked — and the test still passes. Pre-existing pattern, not introduced here; worth replacing with a real layout assertion (Playwright) when the responsive story is tackled.
- **Route card has no text caption** [`TripOverviewMapPanel.tsx:41`] — `EXPERIENCE.md`'s Interaction Primitives and Accessibility Floor both state map previews are "always paired with a text caption/summary (station count…)", and the mockup has `.map-caption` "5 Stationen · Kartenvorschau öffnen". Task 4 explicitly authorized keeping the icon-button instead, so this is task-sanctioned — but the station count now lives in a different component (the stat strip) and the card carries only a "Route" label plus an icon button. Also the populated map wrapper has no border/background where the mockup's `.map-preview` has `1px solid #E4DFD3` on `#F7F4EC` (only the empty state kept a dashed border). Revisit if the caption pattern is standardized across map surfaces.
- **Day-row top padding inflated to 30px to clear the absolutely-positioned feedback panel** [`TripTimeline.tsx:633`] — the story specified `padding: 12px 14px`; the implementation uses `30px 14px 12px 14px` so `TripFeedbackPanel` (absolute, `top: 6, right: 8`) does not clip the accommodation name. Documented as a judgment call, and the clipping fix was verified in-browser — but because the panel is out of flow its width is never reserved, so a long day title in the narrow `xs` layout can still run under it, and every row now carries 18px of dead vertical space. A real grid slot for the panel would be more robust than padding-plus-absolute. Neither DESIGN.md nor EXPERIENCE.md specifies where comments/voting sits, so this needs a design answer first.
